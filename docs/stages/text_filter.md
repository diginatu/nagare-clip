# text_filter — runtime notes

See the [stage overview in AGENTS.md](../../AGENTS.md#text_filter--text-editing-checkpoint-mandatory).

- `text_filter.provider` (default `ollama_chat`) selects the LiteLLM backend; an empty `api_base` falls back to Ollama localhost or is omitted for cloud providers. `text_filter.reasoning_effort` (default unset) is passed to LiteLLM `reasoning_effort` unchanged; unset sends nothing. When `use_llm` is enabled and the orchestrator passes `summary_json` (the summary stage's `summary.json`), this video's whole-video summary, part summaries, and per-video keywords — merged after the constant `text_filter.keywords` list — are appended to the filter LLM's system prompt (`context.build_enhanced_prompt`); a missing, empty, or unreadable `summary.json` degrades to the base prompt. The stem is derived from the input filename (`{stem}.txt`). The default prompt demonstrates repeated-phrase deletion in marker form (`{{映ってる->}}映ってるね`) — real-project runs showed the LLM otherwise performs the deduplication as a bare rewrite, which the marker safety check must drop.
- `_summary_context()` (`text_filter/run.py`) looks up this stem's whole-video summary from `summary.json`'s top-level `video_summaries` map and passes it to `build_enhanced_prompt` as `video_summary`; when present it renders as a `Video summary: <video_summary>` line above the part summaries. An absent/empty entry (stage disabled, older `summary.json` without the field, or this stem missing from the map) means `video_summary=""`, and the prompt is byte-identical to before this field existed.

## Whisper hints

`filter_transcript(..., hints=)` / `run_text_filter(..., hints=)` take `list[str | None]`, one per line (`None` = no hint, `""` = the second recognizer heard nothing, shown as `(none)`). When at least one hint is not `None`, `llm_filter.HINT_INSTRUCTIONS` is appended to the system prompt (after the brief and summary context), and each batch's user message gets `\n\nReference (second recognizer, may be wrong):\n` plus `N: <hint>` for the batch's lines that have one (none → no block). A halving retry carries the hints of its own lines. No hints (or all `None`) leaves the messages byte-identical.

**Where they come from.** `_text_filter_run` (pipeline adapter) calls `whisper.hints.load_line_hints(sentence_split/{stem}.json, whisper/{stem}_whisper.json)` only when `whisper.enabled` is true, so a stale `{stem}_whisper.json` is ignored once the stage is disabled. The hints are used only when their count equals the number of lines in `sentence_split/{stem}.txt`; otherwise a warning is logged and the source runs without hints. A missing or unreadable whisper file also means no hints for that source. See [`whisper.md`](whisper.md).
