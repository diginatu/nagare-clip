# audio_silence — runtime notes

See the [stage overview in AGENTS.md](../../AGENTS.md#audio_silence--audio-silence-jump-cut-detection).

- Audio-silence detection runs Silero VAD v6 in the `transcribe/` worker subproject. The orchestrator (`pipeline/stages.py::_audio_silence_run`) writes ONE request for all sources to `output/audio_silence/vad_request.json` (`{"params": {threshold, min_speech, min_silence, speech_pad}, "sources": [{path, out}]}`) and runs `python -m nagare_transcribe vad` once (`external.build_transcribe_cmd()`, no Docker); the worker writes `{stem}_vad.json` (`{"duration", "speech": [[s, e], ...]}`, seconds). `vad.py` reads it (`read_vad()`) and takes the complement within `[0, duration]` (`silences_from_speech()`, gaps shorter than `min_silence` dropped); `cuts_file.py` writes `{stem}_cuts.txt`, always recording the media duration as a `# media duration: 42.500s` comment (`write_cuts(duration=)`; `read_cuts()` skips it like any comment, `read_media_duration()` reads it, `None` when absent). It is the pipeline's one record of a source's length: a source with no speech (`segments: []`) ends there — its one leading silence line and the footage `intervals` keeps for it (see [`intervals.md`](intervals.md#silence-lines)); without it such a source is 0 s long. The stage is always on (`audio_silence.enabled` and `.noise` are removed and fail config loading; delete a `_cuts.txt` line to keep a silence). Config: `audio_silence.threshold` (default `0.5`), `.min_speech` (s, `0.25`), `.min_silence` (s, `0.5`), `.speech_pad` (s, `0.2`) — distinct from `intervals.silence_threshold` (a word-gap heuristic in the interval stage). The speech regions also define the transcription chunks and lines: transcription joins regions closer than `min_silence` (`vad.join_close_regions()`, the exact complement of the `>= min_silence` cut), so `min_silence` also sets line granularity and a transcript line boundary exists exactly where a cut exists. `_cuts.txt` is human-editable; blank/`#`/malformed/`start>=end` lines are skipped with a warning by `read_cuts()`. Two later stages read `_cuts.txt`: the interval stage's optional `cuts_txt` argument (`run_intervals()`) unions these ranges into the word-timing excludes before invert (omitting it reproduces the prior behaviour exactly, regression-guarded by `tests/intervals/test_run_cuts_merge.py`) and the `gap_context` stage's `snapshot.select_gaps()` picks spans `>= min_gap` (default 3.0s) to snapshot+describe with a vision LLM (see [`docs/stages/gap_context.md`](gap_context.md)). Deleting a cut line therefore keeps that span's audio *and* drops it from gap-context snapshotting — one edit affects both downstream consumers. (`sentence_split` no longer reads it: every cut is already a line boundary, and the stage only splits lines longer than `sentence_split.max_line_seconds`.)
