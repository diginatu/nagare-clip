# audio_silence — runtime notes

See the [stage overview in AGENTS.md](../../AGENTS.md#audio_silence--audio-silence-jump-cut-detection).

- Audio-silence detection runs ffmpeg `silencedetect` in the whisperx container; the orchestrator (`pipeline/stages.py::_audio_silence_run`, via `run_command(stderr_to=...)`) redirects stderr to `{stem}_silencedetect.log`, `detect.py` parses it (duration from ffmpeg's own `Duration:` line, no ffprobe), `cuts_file.py` writes `{stem}_cuts.txt`. Config: `audio_silence.enabled` (default `true`), `.noise` (dB, default `-30.0`), `.min_silence` (s, default `0.8`) — distinct from `intervals.silence_threshold` (a WhisperX word-gap heuristic in the interval stage). `_cuts.txt` is human-editable; blank/`#`/malformed/`start>=end` lines are skipped with a warning by `read_cuts()`. Three later stages read `_cuts.txt`: the interval stage's optional `cuts_txt` argument (`run_intervals()`) unions these ranges into the word-timing excludes before invert (omitting it reproduces the prior behaviour exactly, regression-guarded by `tests/intervals/test_run_cuts_merge.py`); the `sentence_split` stage's `cuts_txt` argument (`run_sentence_split()`) turns spans `>= force_split_min_silence` (default 3.0s, higher than `min_silence`) into forced sentence boundaries — but only where a genuine inter-word gap in the WhisperX timings corroborates the pause, since WhisperX often stretches one word across a silence (see `AGENTS.md` `sentence_split`); and the `gap_context` stage's `snapshot.select_gaps()` picks spans `>= min_gap` (also default 3.0s) to snapshot+describe with a vision LLM (see [`docs/stages/gap_context.md`](gap_context.md)). Deleting a cut line therefore keeps that span's audio, stops it forcing a sentence split, *and* drops it from gap-context snapshotting — one edit affects all three downstream consumers.
